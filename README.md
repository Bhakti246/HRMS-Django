# HRMS Employee Management System

A server-rendered Django Employee Management System with role-based admin and employee workspaces. The application uses Django templates, Django ORM, SQLite for local development, custom CSS, and lightweight vanilla JavaScript for attendance AJAX.

## Main Modules

- Authentication with admin/employee access separation
- Employee, department, and designation management
- Employee profile with verified punch in, punch out, resume, and live timer
- Attendance history with working-time and break-time totals
- Leave application and admin approval/rejection
- Payroll with server-side net salary and attendance deduction calculation
- Recruitment, performance, reports, company settings, and work schedule policy
- Django admin configuration and local seed data

## Local Setup

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Open `http://127.0.0.1:8000/`. The first visit opens company setup when no active
company exists; later visits open sign in. The setup flow creates the company,
owner account, owner employee profile, membership, default organization records,
and signs the owner in automatically. Existing users are routed by their active
company membership role rather than `is_staff`.

Create the first administrator through the environment-backed `bootstrap_admin`
command, then use Django's password-reset flow to activate employee accounts. The
optional `seed_ems` command creates demonstration records with unusable passwords;
it never publishes shared credentials.

## Environment

Copy `.env.example` to your server environment and set real values. This project reads configuration from environment variables directly; no extra dotenv package is required.

Important variables:

- `DJANGO_SECRET_KEY`
- `DJANGO_DEBUG`
- `DJANGO_ALLOWED_HOSTS`
- `DJANGO_CSRF_TRUSTED_ORIGINS`
- `DJANGO_SECURE_SSL_REDIRECT`
- `DJANGO_DB_ENGINE`
- `DJANGO_DB_NAME`

SQLite is the local default. The settings are structured so the database engine/name/user/password/host/port can be supplied later for PostgreSQL without changing application code.

## Production Checklist

```powershell
python manage.py check
python manage.py migrate
python manage.py collectstatic --noinput
```

For Linux/VPS hosting, serve the app with a WSGI server such as Gunicorn or uWSGI behind Nginx. Configure Nginx to serve:

- static files from `staticfiles/`
- media uploads from `media/`

Use HTTPS in production so secure cookies, CSRF protection, HSTS, and redirect settings work as intended.

## Security Notes

- Company membership roles protect management URLs server-side; `is_staff` alone is not authorization.
- Employee attendance, leave, and payroll views are scoped to the logged-in employee.
- Attendance actions do not trust submitted employee IDs; the authenticated user relationship decides ownership.
- Profile photos are validated for extension, MIME type, and maximum size.
- Password validators and production security headers are enabled.

## Project Structure

- `config/` Django settings, root URLs, ASGI/WSGI
- `ems/` models, forms, views, admin, URLs, tests, and seed command
- `templates/` base layout, reusable components, auth, and EMS pages
- `static/css/app.css` custom design system and responsive UI
- `static/js/` lightweight app, AJAX, and attendance scripts
- `media/` uploaded files in development
- `staticfiles/` generated by `collectstatic`
